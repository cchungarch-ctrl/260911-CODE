# NexusPM 專案文件庫 (Documentation Center)

本目錄為專案的知識資產與開發維護核心，劃分為規格文件庫 (`spec/`) 與功能開發計畫庫 (`dev/`)。

---

## 📁 目錄結構

```
doc/
├── spec/                       # 系統正式規格庫（分章節維護）
│   ├── README.md               # 規格書目錄與撰寫維護準則
│   ├── 01_system_architecture.md # 第一章：系統全域架構與技術棧規格
│   ├── 02_core_modules.md      # 第二章：核心功能模組規格
│   ├── 03_data_models.md       # 第三章：資料模型與儲存規格
│   └── 04_ui_ux_standards.md   # 第四章：UI/UX 設計規範與樣式標準
│
└── dev/                        # 功能開發計畫庫（事前討論與計畫）
    ├── README.md               # 開發工作流程與規範說明
    ├── template_plan.md        # 新功能開發計畫範本
    └── plan_<功能名稱>.md       # 進行中或已規劃之功能計畫檔案
```

---

## 🔄 標準開發工作流程 (Development Workflow)

所有後續功能開發與修改，皆必須嚴格遵守以下五步驟流程：

```
[1. 需求討論與釐清] ──> [2. 撰寫計畫 (doc/dev/plan_<功能名稱>.md)] ──> [3. 依計畫實作代碼] ──> [4. 驗收與測試] ──> [5. 回寫正式規格 (doc/spec/)]
```

1. **功能開發前先討論**：與使用者充分討論功能範疇、使用情境、介面設計與技術架構。
2. **編寫計畫並放進 `doc/dev/`**：以 `plan_<功能名稱>.md` 命名，詳細記錄實作項目與驗證步驟。
3. **參照計畫進行開發**：開發期間嚴格遵循該計畫之設計原則與步驟。
4. **驗收與測試**：確認本機伺服器運行正常、無報錯、功能符合預期。
5. **功能開發完成後回寫 `doc/spec/`**：將新功能之正式規格、資料型態、API 或畫面行為更新至對應章節中，保持規格書最新。
